# Zotero PDF Sticky Notes

Zotero PDF Sticky Notes 是一个 macOS 优先的 Zotero 插件原型。它允许用户在原文 PDF
中放置一种特殊的 Zotero 便签批注，并通过单击该便签，打开同一篇文献下独立的手写笔记
PDF。

> 原型状态：`0.1.4`。当前兼容范围严格锁定为 Zotero `9.0.6`。Zotero 10 和其他
> Zotero 9 小版本尚未验证，插件不会声称兼容这些版本。

## 原型中已实现的能力

- 从原文 PDF 阅读器工具栏进入“添加手写便签”模式。
- 使用 Zotero 原生 note annotation 保存便签页码和 PDF 坐标。
- 只认领本次放置操作实际生成的批注 key；用户切换工具会取消插件放置状态。
- 为每个插件便签创建一个独立的一页空白 PDF。
- 笔记 PDF 作为普通 Zotero 管理附件，直接挂在原文所属文献记录下。
- 首次放置和关联成功后，立即打开新建的笔记 PDF 小窗口。
- 单击插件便签时，尝试在独立的小型 Zotero 阅读器窗口中打开关联笔记。
- 笔记窗口复用 Zotero 原生阅读、缩放、画笔、擦除、撤销和重做能力。
- 在笔记 PDF 末尾添加空白页。
- 加页前等待 Zotero 保存当前笔迹及擦除事务；同一笔记的加页操作串行执行。
- 加页时阻止同一附件启动新阅读器，并等待已在初始化的阅读器完成后再统一保存和冻结。
- 加页与 Zotero 原生旋转、删页、导入等 PDFWorker 操作进入同一个全局串行队列。
- 使用同目录临时文件、原子重命名、恢复副本和写后页数校验更新 PDF。
- 远程附件下载超时或取消后立即反馈，但在底层请求真正结束前阻止后续文件访问。
- 将 Zotero `IOUtils` 返回的跨 realm 字节复制到插件 realm 后再交给 `pdf-lib`。
- 区分缺失关联、已删除附件、未下载附件、文件缺失及保存失败。
- 右键插件便签可在明确确认后永久删除便签，并把关联笔记 PDF 移入 Zotero 回收站。
- 成对删除提交后，等待所有正在初始化的原文阅读器就绪，再显式清除其中的便签视图；
  单个视图清除失败只记录错误，数据库删除不会因此被误报为失败。
- 同一父文献下的创建、成对删除和编号分配串行；编号复用有效附件中的最小空缺。
- 读取父条目子项、附件标题、tag 和 relation 前显式加载 Zotero 的懒加载数据；
  加载或创建失败时清理本次刚创建的便签和附件。
- 插件停用时移除工具栏元素和监听器，不删除用户 PDF 或批注。

以上 Zotero 内交互仍须按测试文档完成客户端验收后，才能作为正式支持能力发布。

## 文件组织

一篇文献下的结构如下：

```text
文献记录
├── Original.pdf
├── Sticky Notes 1.pdf
└── Sticky Notes 2.pdf
```

原文和笔记都是普通附件。笔记附件可以不经过便签，直接从 Zotero 附件列表打开。

每个插件便签关联一个笔记附件；同一篇文章可以拥有多个便签和多个笔记 PDF。

## 安装原型

1. 获取 `dist/zotero-pdf-sticky-notes-0.1.4.xpi`。
2. 在 Zotero 中打开“工具 → 插件”。
3. 打开插件管理器的齿轮菜单，选择“从文件安装插件…”。
4. 选择 `.xpi` 文件，并按提示完成安装。
5. 重启 Zotero。
6. 在“工具 → 插件”中确认 Zotero PDF Sticky Notes 已启用。

当前 XPI 仅允许安装到 Zotero 9.0.6。`0.1.2` 在独立的 `developer` profile 中可以创建便签
和有效空白 PDF，但首次自动打开及随后单击都失败：跨 realm 的有效 `Uint8Array` 被
`pdf-lib` 误报为 `NaN`。从附件列表打开后可以书写，但关闭时插件读取受 Gecko 保护的删除
参数并报 `Permission denied to access property "length"`，因此无法确认最后一笔或擦除已经
完整保存。普通删除便签会按原设计保留 PDF，所以仍存在的 `Sticky Notes 1.pdf` 会继续占用
编号。

`0.1.3` 在文件边界复制 PDF 字节，完全不再包装或读取 reader-realm 的删除参数，改为观察
chrome `Reader.annotationItemIDs` 确认已持久化墨迹的擦除，并新增明确确认的成对删除入口。
后续客户端测试发现：成对删除后笔记 PDF 确实进入回收站，便签数据库记录也已永久删除，
但当前打开的原文页面会留下一个看似普通便签的 UI 残影；关闭并重新打开原文后残影消失。

源码核对确认这是 Zotero 9.0.6 的通知顺序造成的：笔记附件的 `modify` 通知先刷新并移除
便签 ID，随后 `delete` 通知便无法再定位应从页面清除的图标。`0.1.4` 保持原子事务不变，
在提交成功后显式同步所有原文阅读器。该修复已自动测试，仍待 Zotero GUI 复测。
`0.1.0`、`0.1.1`、`0.1.2` 和 `0.1.3` 不应继续用于本轮验收；请升级到 `0.1.4`。

## 使用方法

### 准备原文

原文 PDF 必须已经作为附件挂在一条 Zotero 文献记录下。如果 PDF 是没有父条目的独立
附件，插件会停止创建，并提示先将它拖到一条现有文献记录下，或使用 Zotero 的“创建父
条目”功能。

插件不会擅自创建内容不明的父文献记录。新笔记附件始终归属于原文当前所属的文献记录。

只读文献库或不允许编辑文件的群组文献库不能创建手写便签。

### 创建和打开手写便签

1. 在 Zotero 阅读器中打开原文 PDF。
2. 单击工具栏中的“添加手写便签”按钮。
3. 在 60 秒内单击 PDF 某一页的具体位置。
4. 插件创建一个 Zotero 便签批注，并在同一父文献下创建 `Sticky Notes N.pdf`，随后立即
   打开它的独立阅读器窗口。
5. 以后单击该便签，会打开或复用同一个关联笔记窗口。
6. 也可以右键单击插件便签，选择“打开手写笔记”。

放置超过 60 秒时，插件会退出放置模式并显示超时提示；需要重新单击“添加手写便签”。
普通 Zotero 便签没有插件标识，继续使用 Zotero 原有交互。
插件便签有意沿用原生便签的外观；区别保存在 Zotero tag 和双向关系中，验收重点是单击后
是否打开关联 PDF，而不是图标是否不同。

上述首次自动打开和修复后的单击行为尚待 `0.1.4` 客户端复测；窗口复用、窗口尺寸及焦点
返回仍为 `NOT RUN`。

### 手写和加页

在笔记窗口中使用 Zotero 原生工具进行查看、翻页、缩放、画笔书写、擦除、撤销和重做。

单击“添加空白页”后，插件会：

1. 等待所有已打开的同一笔记阅读器保存当前批注；
2. 避开正在进行的 Zotero 同步；
3. 冻结相关阅读视图；
4. 在 PDF 末尾追加一页并校验写入后的页数；
5. 更新 Zotero 附件文件状态；
6. 刷新相关阅读器，并尝试在当前笔记窗口显示新页。

第一张空白页为 A4。后续页面沿用该笔记最后一页的尺寸。

## 数据如何保存

笔记由两部分组成：

- 空白页面属于实际 PDF 文件；
- 画笔笔迹、擦除结果等批注由 Zotero 原生批注系统保存在 Zotero 数据库中。

因此，直接从 Zotero 存储目录复制原始 PDF 文件，不保证其中已经包含手写笔迹。需要一个
可在其他 PDF 阅读器中独立显示笔迹的文件时，应使用 Zotero 的批注 PDF 导出功能。

便签和笔记附件的关联使用 Zotero item URI、条目关系和可同步的 Zotero tag 保存：

- 便签 marker tag：`zotero-pdf-sticky-notes:sticky:v1`
- 笔记附件 marker tag：`zotero-pdf-sticky-notes:note:v1`
- 双向关联：`dc:relation`，值只保存真实 Zotero item URI

URI 基于所属 library 和稳定 item key，不依赖附件标题，所以重命名笔记附件不应改变关联。
marker 使用普通 Zotero tag；手工删除这两个 tag 会使插件不再把相应条目识别为插件便签或
笔记。重启、重命名和同步往返仍须完成客户端实测后才能标为 `PASS`。

更完整的数据模型和写入流程见 [架构说明](docs/ARCHITECTURE.md)。

## 导出包含手写内容的 PDF

预期操作方式如下：

1. 在 Zotero 阅读器中打开笔记附件。
2. 等待当前笔迹保存完成。
3. 选择“文件 → 另存为…”。
4. 将导出的 PDF 保存到 Zotero 存储目录之外。
5. 使用 macOS“预览”或另一个非 Zotero PDF 阅读器打开导出文件。
6. 检查所有页面、加页后的页数及每页笔迹。

Zotero 9.0.6 源码显示，“另存为…”会进入 Zotero 的 annotated PDF 导出流程。项目目前尚未
实际检查导出文件，因此此能力仍为 `NOT RUN`；通过 `Z-21` 前不得写成“已验证”。

## 错误和恢复

- 关联附件已删除：提示目标已删除，不自动新建替代笔记。
- 附件尚未下载：在 Zotero 文件同步可用时尝试下载；下载失败会显示错误。
- Zotero 底层下载无法立即停止：先返回取消或超时错误；该附件后续操作和插件停用等待原请求
  结束，避免下载晚到并覆盖加页结果。
- 本地文件缺失且文件同步关闭：明确提示文件缺失。
- 文件不可读：停止打开或加页，不覆盖文件。
- 创建过程中失败：尝试删除本次新建的便签和笔记附件；回滚不完整时写入 Zotero 错误日志。
- 加页写入或校验失败：尝试恢复原文件。
- 检测到读取后的 PDF 被其他进程修改：拒绝覆盖，并恢复检测到的较新文件。
- 自动恢复失败：保留恢复副本、隔离失败文件，并把附件标为同步冲突，避免上传不可信文件。
- 新页已经写入但阅读器刷新失败：保留新 PDF 和恢复副本，并提示用户重新打开附件。
- 关闭笔记窗口时仍有未保存笔迹：尝试先完成保存；保存失败时保持窗口打开并显示错误。
- 擦除操作的 Zotero 数据库事务失败：保存屏障报错，不把擦除误判为已保存。
- 成对删除前保存已打开笔记的手写；保存失败时不删除任何条目。删除事务真正回滚时
  重载条目和父子缓存、恢复全局 relation index；数据库已提交后才出现的 host callback
  异常只记录日志，不会重建已删除的关联或误报删除失败。
- Zotero 9.0.6 成对删除通知留下的页面残影：事务成功后等待正在初始化的原文 reader，
  再按 annotation key 清除所有已打开视图；只有清除成功后才同步内部 ID。

恢复副本的具体路径会随错误信息显示。确认数据无误前不要删除该文件。这些失败路径已有
部分单元测试覆盖，但 Zotero 集成错误提示及真实文件恢复仍为 `NOT RUN`。

## 删除、停用和卸载

- 使用 Zotero 原生 Delete/Backspace 删除便签时，默认不会删除关联的笔记附件。
- 要同时处理两者，请右键插件便签，选择“删除便签并将笔记 PDF 移到回收站…”，再在确认
  框中选择“删除两者”。便签会永久删除；笔记 PDF 及其中的原生手写批注会移入 Zotero
  回收站，清空回收站前可以恢复。
- 从回收站恢复 PDF 不会恢复已经永久删除的便签或原关联。同一父文献的新笔记使用所有未进
  回收站附件标题中的最小空缺编号；仍处于活动状态的孤立 PDF 继续占号，恢复旧 PDF 后可能
  出现同名附件，但稳定 item URI 关联不依赖标题。
- 删除笔记附件后，再单击便签应显示目标已删除或关联无效。
- 停用或卸载插件不会主动删除原文、笔记 PDF、Zotero 原生批注或关系元数据。
- 停用插件后，笔记附件应仍能从附件列表使用 Zotero 阅读器打开。
- 停用后不再提供便签直达窗口和“添加空白页”按钮。

`0.1.3` 已确认成对删除的数据结果正确，但页面残影使该交互验收失败；`0.1.4` 修复后的
即时清除、恢复、停用和卸载场景仍为 `NOT RUN`。

## 同步说明

实现沿用 Zotero 的条目数据同步和存储附件同步机制；加页后会把附件标记为需要上传。代码
还会尽量避免 Zotero 正在同步时替换笔记文件。

当前版本尚未完成两个独立 Zotero profile 或两台设备之间的往返验证，因此不正式声称
支持同步。发布前至少需要验证：

- 便签关系元数据能在另一配置解析；
- 笔记附件能正常下载；
- 重命名后关联不变；
- 在另一配置中书写、加页并同步回来后，页数和笔迹正确；
- 同步冲突不会造成无提示的数据丢失。

### iPad 手写工作流

`.xpi` 只在 macOS/Windows/Linux 的 Zotero 桌面端运行，不会同步或安装到 Zotero iPad
客户端。Zotero 团队也明确说明 iOS 是原生 Swift 应用，不能运行桌面插件。Better Notes
一类插件在桌面端写入的标准 Zotero 数据可以同步并由 iPad 原生界面显示，这不表示插件
代码或事件监听器在 iPad 上运行。[Zotero 官方说明](https://forums.zotero.org/discussion/116251/zotero-for-ipad-tools-and-pligins)

本项目面向 iPad 的可行工作流是：

1. 在 Mac 上用插件创建便签和普通的 Zotero 管理笔记 PDF；如需多页，先在 Mac 笔记窗口
   中添加足够的空白页。
2. 完成 Zotero 数据与文件同步。
3. 在 iPad 上展开同一文献，从附件列表打开 `Sticky Notes N.pdf`，使用 Apple Pencil 和
   Zotero 原生画笔书写。
4. 同步回 Mac 后，再由 Mac 原文中的插件便签打开同一个笔记 PDF。

iPad 原生 Zotero 当前不会运行本插件的便签点击监听器或加页按钮，因此本 XPI 无法给原文
便签图标增加单击、双击或长按动作。`dc:relation` 会同步，但当前 iOS reader 的批注模型和
动作列表没有消费该关系的“打开相关附件”入口；把 `zotero://open-pdf/...` 写进批注 comment
也不会变成可点击链接。上述 iPad 往返仍为 `NOT RUN`，通过真实账户测试前不声称已经支持。

iOS 本身支持直接打开附件的 `zotero://open-pdf/...` 深链，但当前可靠入口不在 PDF 便签
图标上。[iOS 深链实现](https://github.com/zotero/zotero-ios/blob/805b3e482579f1af544e870a47992f7f7ff4cfe1/Zotero/Controllers/CustomURLController.swift)
如果要在原文位置提供直达，可另做一个隔离实验：把标准 PDF Link annotation 热区写进
原文 PDF，并指向关联附件。该方案会修改原文文件、触发整文件同步，还需要 iPad 真机验证
点击、下载、缓存刷新和删除生命周期，因此 `0.1.4` 未包含它，也不会在未确认产品取舍前
默认修改用户原文。准确实现原生便签长按/双击则需要 Zotero iOS 上游增加功能。

## 从源码构建

要求：

- Node.js 24 LTS 或更高版本；
- npm；
- 用于手工验收的 Zotero 9.0.6 独立测试配置。

```bash
npm ci
npm run typecheck
npm test
npm run build
```

完整检查：

```bash
npm run check
```

构建输出：

```text
dist/zotero-pdf-sticky-notes-0.1.4.xpi
```

`npm run build` 会同步第三方许可证、打包运行时代码、执行类型检查并检查 XPI。`pdf-lib`
及其运行时依赖被编入 XPI，用户不需要安装 Node.js 或 `node_modules`。

## 已知限制

- 只锁定 Zotero 9.0.6；Zotero 10 未支持。
- 便签单击、批注保存屏障、阅读器刷新和窗口管理依赖 Zotero 9.0.6 的内部阅读器 API。
- 小窗口复用、尺寸、焦点返回和位于原文前方的行为仍须 macOS 客户端验证。
- 只支持在末尾添加空白页，不支持插入、删除、重排或选择页面模板。
- 第一页固定为 A4；没有纸张尺寸或背景样式设置。
- 当前不提供重新关联、孤立笔记扫描或修复 UI。
- 原生删除便签不会自动清理笔记附件；只有右键菜单中的明确确认操作会执行成对处理。
- 安装或重新启用插件时已经打开的 PDF 可能不会立即补出工具栏按钮；请关闭并重新打开该
  PDF。Zotero 9.0.6 的公开 reader toolbar 事件不会向现有视图重放。
- 笔记作为 Zotero 主窗口标签打开且仍在保存时，不要立即使用“移到新窗口”；应等待保存
  完成后再移动。插件要求的便签打开流程本身使用独立窗口。
- 不处理两个客户端同时修改同一个笔记 PDF 的冲突。
- iPad 可以使用同步后的普通笔记 PDF 和原生 ink 批注，但不能运行本 XPI；iPad 上需从同一
  文献的附件列表打开笔记，也不能使用插件的“添加空白页”按钮或从便签图标执行插件动作。
- Zotero 9.0.6 的部分存储后端可能无法立即取消下载；插件会优先保证文件安全，底层下载在
  后台结束前，同一附件不能再次打开或加页，停用插件也可能被延迟。
- 同步、完整导出和插件停用后的读取仍为发布前验证项。
- 自动更新地址已指向 GitHub Releases；上传首个包含 `release/update.json` 的 Release 前，
  该地址不会提供更新文件。
